# 智云实验室前端项目说明

这份文档写给后续维护和二次开发使用。重点不是介绍项目背景，而是告诉你：代码在哪里、怎么启动、页面怎么找、接口怎么接、一个功能应该改哪些文件。

前端目录：`web`

核心技术：

- Vue 3
- Vite
- Element Plus

- Axios
- ECharts

项目类型：实验室协同管控平台的管理端前端。

## 3. 环境变量与接口代理

开发环境配置文件：

```text
web/.env.development
```

当前配置：

```env
VITE_API_MODE=server
VITE_API_BASE_URL=/api
VITE_API_PROXY_TARGET=http://127.0.0.1:8080
```

相关读取位置：

```text
web/src/api/config.js
```

含义：

- `VITE_API_MODE=server` 表示使用真实后端接口。
- `VITE_API_BASE_URL=/api` 表示前端请求以 `/api` 开头。
- `VITE_API_PROXY_TARGET=http://127.0.0.1:8080` 表示开发服务器把 `/api` 代理到后端 `8080`。

Vite 代理配置：

```text
web/vite.config.js
```

实际效果：

```text
前端请求：/api/devices
代理到：  http://127.0.0.1:8080/devices
```

如果接口不通，先检查：

1. 后端是否启动。
2. 后端端口是否是 `8080`。
3. `.env.development` 是否是 server 模式。
4. 浏览器 Network 中请求地址是否是 `/api/...`。
5. Vite 是否重启过，环境变量改动后需要重启 dev server。

## 6. 接口封装说明

### 6.1 接口地址

接口地址集中在：

```text
web/src/api/endpoints.js
```

示例：

```js
devices: {
  list: '/devices',
  batch: '/devices/batch',
  reset: '/devices/reset',
  inventory: (id) => `/devices/${id}/inventory`,
  transfer: (id) => `/devices/${id}/transfer`,
}
```

新增接口时，优先在这里统一加路径。

### 6.2 Axios 实例

Axios 实例：

```text
web/src/api/http.js
```

这里做了几件事：

- 设置 `baseURL`。
- 设置请求超时。
- 请求前自动带上 JWT Token。
- 响应里如果业务 `code !== 200`，会转成错误。
- 遇到 `401` 会清理登录状态并跳转登录页。

### 6.3 业务服务

接口服务目录：

```text
web/src/api/services/
```

常见文件：

```text
auth.js                  登录、退出、用户信息
basicResources.js        实验室、设备、预约、报修等基础资源
collectionService.js     通用列表资源服务工厂
users.js                 用户列表、用户相关接口
```

新增接口调用推荐写法：

```js
import { API_ENDPOINTS } from '../endpoints'
import http from '../http'

export async function listSomething() {
  const { data } = await http.get(API_ENDPOINTS.something.list)
  return data.data || []
}
```

## 7. Mock 与真实接口

配置位置：

```text
web/src/api/config.js
```

```js
export const API_MODE = import.meta.env.VITE_API_MODE || 'server'
export const API_USE_MOCK = API_MODE !== 'server'
```

含义：

- `server`：请求真实后端。
- 非 `server`：部分服务会走 localStorage mock 数据。

设备资产模块目前既支持真实后端接口，也兼容部分 mock/localStorage 场景。

## 8. 路由、菜单与权限

### 8.1 路由配置

路由主文件：

```text
web/src/router/index.js
```

页面组件映射在 `routeComponentMap`：

```js
const routeComponentMap = {
  LabAdminDeviceManagement: () => import('../views/devices/DeviceManagement.vue'),
}
```

### 8.2 菜单模块

菜单和角色模块定义：

```text
web/src/constants/routeModules.js
```

每个模块大概长这样：

```js
{
  path: '/lab-admin/devices',
  routePath: 'lab-admin/devices',
  name: 'LabAdminDeviceManagement',
  title: '设备资产',
  menuTitle: '设备资产',
  description: '管理设备台账、状态、维护记录和资产信息。',
  roleScope: 'labAdmin',
  showInMenu: true,
}
```

新增菜单页面通常要改：

1. `constants/routeModules.js`
2. `router/index.js` 的 `routeComponentMap`
3. `views/xxx/XxxPage.vue`

### 8.3 权限控制

权限配置：

```text
web/src/constants/permissions.js
```

示例：

```js
设备资产: ['/lab-admin/devices']
```

登录后，路由守卫会读取用户权限，判断当前路径是否允许访问。

如果新增页面需要权限控制，需要同步加到 `PERMISSION_ROUTE_MAP`。

## 9. 页面组织习惯

当前项目较推荐的页面组织方式：

```text
views/模块名/
├─ XxxManagement.vue              页面容器
└─ components/
   ├─ XxxHeader.vue               顶部区域
   ├─ XxxFilterBar.vue            筛选区
   ├─ XxxListTable.vue            表格
   ├─ XxxEditorDialog.vue         新增/编辑弹窗
   └─ XxxDetailPanel.vue          详情区域

composables/
└─ useXxxManagement.js            页面业务逻辑
```

建议：

- 页面容器负责布局。
- 子组件负责展示和事件抛出。
- 数据请求、过滤、提交、删除等逻辑放在 `composables`。
- API 调用放在 `api/services`。

这样以后改功能更容易定位。

## 10. 设备资产模块详解

设备资产是目前比较完整的模块，可作为后续其它模块开发参考。

### 10.1 主页面


- 保存当前勾选设备。

- 处理路由 query，例如根据 `?device=xxx` 自动选中设备。

### 10.2 核心逻辑

```text
web/src/composables/useDeviceManagement.js
```

主要内容：

- 设备状态选项。
- 设备分类选项。

- 设备列表加载。
- 实验室和责任人选项加载。
- 搜索筛选。
- 新增设备。
- 编辑设备。
- 删除设备。
- 批量删除。
- 盘点记录提交。
- 调拨记录提交。
- Excel/CSV 批量导入。
- 下载导入模板。
- 导出设备清单。

### 10.3 设备表格

```text
web/src/views/devices/components/DeviceListTable.vue
```

负责：

导出工具：


支持：

- 下载 `.xlsx` 模板。
- 导出设备清单 `.xlsx`。
- 导出盘点记录 `.xlsx`。
- 导入 `.xlsx`。
- 导入 `.csv`。

导入逻辑在：

```text

```

关键函数：

- `downloadDeviceImportTemplate`
- `importDevicesFromFile`
- `prepareImportRows`
- `buildImportedDevice`
- `exportDevices`
- `exportInventoryRecords`

- 根据资产编号判断新增还是更新。

- 实验室名称会尝试匹配实验室列表。
- 责任人名称会尝试匹配用户列表。
- 不符合要求的行会跳过并提示。

## 12. 表单开发建议

- `el-select`
- `el-option`
- `el-date-picker`
- `el-switch`

弹窗组件推荐写法：

```vue
<script setup>
import { computed } from 'vue'

const props = defineProps({
  modelValue: Boolean,
})

const emit = defineEmits(['update:modelValue', 'submit'])

const visible = computed({
  get: () => props.modelValue,
  set: (value) => emit('update:modelValue', value),

```

```vue

```

## 15. 登录与会话

```text
web/src/api/services/auth.js
```

```text
web/src/constants/auth.js
```


流程：

4. 如果后端返回 401，清理缓存并跳转 `/login`。

## 16. 常见问题排查

### 16.1 页面白屏

检查：

1. 控制台是否有 Vue 编译错误。
2. 路由组件路径是否写错。
3. `routeComponentMap` 是否缺少组件映射。
4. `npm.cmd run build` 是否能通过。

### 16.2 接口 404

检查：

1. `endpoints.js` 路径是否正确。
2. 后端 Controller 路径是否存在。
3. 是否需要 `/api` 前缀。
4. Vite 代理是否启动。

### 16.3 接口 500

检查：

1. 后端控制台异常。
2. 请求体字段类型是否正确。
3. 是否传了字符串 id 给后端 Long。
4. 数据库字段是否存在。
5. Mapper XML 参数是否匹配。

### 16.4 页面显示旧数据

检查：

1. 是否走了 mock localStorage。
2. `.env.development` 是否是 `VITE_API_MODE=server`。
3. 浏览器 localStorage 是否有旧 mock 数据。
4. 后端接口是否真的返回新数据。
