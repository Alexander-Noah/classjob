# 智云实验室前后端线上部署指南

本文档用于将“智云实验室——基于数据驱动的实验室协同管控平台”部署到线上服务器。推荐架构为：Nginx 对外提供 HTTPS 和前端静态资源，并将 `/api` 与 WebSocket 请求反向代理到内网 Spring Boot 后端服务。

## 1. 部署架构

```text
用户浏览器
  |
  | HTTPS 80/443
  v
Nginx
  |-- 静态资源: /opt/smart-lab/web/dist
  |-- REST API: /api/* -> http://127.0.0.1:8080/*
  |-- WebSocket: /ai-assistant/ws、/ws/ai-assistant -> http://127.0.0.1:8080
  v
Spring Boot 后端
  |-- MySQL: smart_lab_basic
  |-- Redis: 可选，用于缓存与运行状态
  |-- OSS: 可选，用于对象存储
  |-- 通义千问/DashScope: 可选，用于 AI 能力
  |-- Vosk/Python: 可选，用于语音与课表采集能力
```

## 2. 服务器准备

建议生产环境至少使用 2 核 4GB 内存，推荐 4 核 8GB 以上。服务器需安装：

- JDK 17 或更高版本
- Maven 3.8 或更高版本，用于后端构建
- Node.js 18 或更高版本、npm 9 或更高版本，用于前端构建
- MySQL 8.0 或兼容版本
- Redis 6.0 或更高版本，可选
- Nginx 1.20 或更高版本
- Python 3，可选，启用课表采集能力时需要

建议开放端口：

- `80`、`443`：对外访问
- `8080`：后端服务端口，仅允许本机或内网访问
- `3306`、`6379`：数据库与 Redis 端口，仅允许应用服务器访问

## 3. 推荐目录结构

```text
/opt/smart-lab/
  backend/
    app.jar
    .env
    logs/
    data/
    Python/
    vosk-model-small-cn-0.22/
  web/
    dist/
```

创建部署用户与目录：

```bash
sudo useradd -r -s /usr/sbin/nologin smartlab
sudo mkdir -p /opt/smart-lab/backend/logs /opt/smart-lab/backend/data /opt/smart-lab/web
sudo chown -R smartlab:smartlab /opt/smart-lab
```

## 4. 数据库初始化

创建业务库与账号：

```sql
CREATE DATABASE smart_lab_basic
  DEFAULT CHARACTER SET utf8mb4
  DEFAULT COLLATE utf8mb4_unicode_ci;

CREATE USER 'smart_lab'@'%' IDENTIFIED BY '替换为强密码';
GRANT ALL PRIVILEGES ON smart_lab_basic.* TO 'smart_lab'@'%';
FLUSH PRIVILEGES;
```

后端启动时会自动初始化核心业务表。仓库中也保留了若干迁移脚本，例如：

- `web/database/migrations/20260702_device_runtime_iot_phase1.sql`
- `web/database/migrations/20260704_lan_teacher_student_autoconnect.sql`

如线上数据库已有历史数据，建议先备份数据库，再按发布日期顺序审阅并执行迁移脚本。

## 5. 后端构建

在开发机或构建机执行：

```bash
cd Backend
mvn clean package -DskipTests
```

构建产物通常位于：

```text
Backend/target/Backend-0.0.1-SNAPSHOT.jar
```

上传到服务器：

```bash
scp Backend/target/Backend-0.0.1-SNAPSHOT.jar user@server:/tmp/app.jar
sudo mv /tmp/app.jar /opt/smart-lab/backend/app.jar
sudo chown smartlab:smartlab /opt/smart-lab/backend/app.jar
```

## 6. 后端生产环境变量

在服务器创建 `/opt/smart-lab/backend/.env`：

```bash
SERVER_PORT=8080

SMART_LAB_DB_URL=jdbc:mysql://127.0.0.1:3306/smart_lab_basic?useUnicode=true&characterEncoding=utf8&useSSL=false&serverTimezone=Asia/Shanghai&allowPublicKeyRetrieval=true
SMART_LAB_DB_USERNAME=smart_lab
SMART_LAB_DB_PASSWORD=替换为数据库密码

SMART_LAB_JWT_SECRET=替换为至少32位的随机字符串
ACADEMIC_CREDENTIAL_SECRET=替换为至少32位的随机字符串

SMART_LAB_CORS_ALLOWED_ORIGINS=https://你的域名
SMART_LAB_CORS_ALLOWED_ORIGIN_PATTERNS=https://你的域名

SMART_LAB_REDIS_HOST=127.0.0.1
SMART_LAB_REDIS_PORT=6379
SMART_LAB_REDIS_DATABASE=0
SMART_LAB_REDIS_PASSWORD=
SMART_LAB_REDIS_HEALTH_ENABLED=true

DASHSCOPE_API_KEY=替换为通义千问APIKey
TONGYI_API_KEY=替换为通义千问APIKey

SMART_LAB_OSS_ENABLED=false
ALIYUN_OSS_ENDPOINT=
ALIYUN_OSS_BUCKET=
ALIYUN_OSS_ACCESS_KEY_ID=
ALIYUN_OSS_ACCESS_KEY_SECRET=
ALIYUN_OSS_PUBLIC_BASE_URL=

VOSK_MODEL_PATH=/opt/smart-lab/backend/vosk-model-small-cn-0.22
TIMETABLE_CRAWLER_PYTHON=/usr/bin/python3
TIMETABLE_CRAWLER_SCRIPT_PATH=/opt/smart-lab/backend/Python/school_timetable_crawler.py
TIMETABLE_CRAWLER_WORKDIR=/opt/smart-lab/backend/Python
TIMETABLE_CRAWLER_OUTPUT_DIR=/opt/smart-lab/backend/data/timetable-crawler
```

注意事项：

- `.env` 不要提交到 Git 仓库。
- `SMART_LAB_JWT_SECRET` 与 `ACADEMIC_CREDENTIAL_SECRET` 必须使用强随机字符串，且长度不少于 32 位。
- 如果暂不使用 OSS、DashScope、Vosk 或课表采集能力，可以保留空值或关闭对应开关。
- 生产环境不要使用代码中的默认密钥、默认密码或本地路径。

设置权限：

```bash
sudo chown smartlab:smartlab /opt/smart-lab/backend/.env
sudo chmod 600 /opt/smart-lab/backend/.env
```

## 7. 后端 systemd 服务

创建 `/etc/systemd/system/smart-lab-backend.service`：

```ini
[Unit]
Description=Smart Lab Backend
After=network.target mysql.service

[Service]
User=smartlab
Group=smartlab
WorkingDirectory=/opt/smart-lab/backend
EnvironmentFile=/opt/smart-lab/backend/.env
ExecStart=/usr/bin/java -jar /opt/smart-lab/backend/app.jar
Restart=on-failure
RestartSec=5
SuccessExitStatus=143

[Install]
WantedBy=multi-user.target
```

启动服务：

```bash
sudo systemctl daemon-reload
sudo systemctl enable smart-lab-backend
sudo systemctl start smart-lab-backend
sudo systemctl status smart-lab-backend
```

查看日志：

```bash
journalctl -u smart-lab-backend -f
```

## 8. 前端构建

在开发机或构建机执行：

```bash
cd web
npm install
```

创建或确认 `web/.env.production`：

```bash
VITE_API_MODE=server
VITE_API_BASE_URL=/api
VITE_API_TIMEOUT=10000
```

执行构建：

```bash
npm run build
```

构建产物位于：

```text
web/dist
```

上传到服务器：

```bash
scp -r web/dist user@server:/tmp/smart-lab-dist
sudo rm -rf /opt/smart-lab/web/dist
sudo mv /tmp/smart-lab-dist /opt/smart-lab/web/dist
sudo chown -R smartlab:smartlab /opt/smart-lab/web/dist
```

## 9. Nginx 配置

示例配置 `/etc/nginx/conf.d/smart-lab.conf`：

```nginx
server {
    listen 80;
    server_name 你的域名;

    client_max_body_size 50m;

    root /opt/smart-lab/web/dist;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;
    }

    location /api/ {
        proxy_pass http://127.0.0.1:8080/;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_connect_timeout 60s;
        proxy_send_timeout 120s;
        proxy_read_timeout 120s;
    }

    location /ai-assistant/ws {
        proxy_pass http://127.0.0.1:8080/ai-assistant/ws;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 3600s;
    }

    location /ws/ai-assistant {
        proxy_pass http://127.0.0.1:8080/ws/ai-assistant;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 3600s;
    }
}
```

检查并重载：

```bash
sudo nginx -t
sudo systemctl reload nginx
```

生产环境建议使用 HTTPS。可通过云厂商证书、Nginx 证书配置或 Certbot 配置 TLS。

## 10. 发布流程

后端发布：

```bash
sudo systemctl stop smart-lab-backend
sudo cp /opt/smart-lab/backend/app.jar /opt/smart-lab/backend/app.jar.bak.$(date +%Y%m%d%H%M%S)
sudo mv /tmp/app.jar /opt/smart-lab/backend/app.jar
sudo chown smartlab:smartlab /opt/smart-lab/backend/app.jar
sudo systemctl start smart-lab-backend
journalctl -u smart-lab-backend -n 100 --no-pager
```

前端发布：

```bash
sudo mv /opt/smart-lab/web/dist /opt/smart-lab/web/dist.bak.$(date +%Y%m%d%H%M%S)
sudo mv /tmp/smart-lab-dist /opt/smart-lab/web/dist
sudo chown -R smartlab:smartlab /opt/smart-lab/web/dist
sudo nginx -t
sudo systemctl reload nginx
```

回滚：

- 后端：将上一版 `app.jar.bak.*` 恢复为 `app.jar`，重启 `smart-lab-backend`。
- 前端：将上一版 `dist.bak.*` 恢复为 `dist`，重载 Nginx。
- 数据库：涉及结构变更前必须备份，必要时按备份恢复。

## 11. 上线验收

上线后建议逐项检查：

- `systemctl status smart-lab-backend` 状态为 `active`
- `journalctl -u smart-lab-backend -n 100 --no-pager` 无启动异常
- `curl http://127.0.0.1:8080/actuator/health` 能返回服务状态
- `nginx -t` 配置检查通过
- 浏览器访问 `https://你的域名` 能打开前端页面
- 登录、实验室列表、设备状态、联动控制等核心接口能正常返回
- 浏览器开发者工具中 `/api/*` 请求不是 404、502 或 CORS 错误
- AI 助手 WebSocket 能建立连接，没有 400、502 或连接升级失败
- 上传、OSS、语音识别、课表采集等可选功能按实际启用情况验证

## 12. 常见问题排查

| 现象 | 可能原因 | 处理方式 |
| --- | --- | --- |
| 前端页面刷新后 404 | Nginx 未配置 `try_files` | 确认 `location /` 使用 `try_files $uri $uri/ /index.html;` |
| `/api` 返回 502 | 后端未启动、端口不通或代理地址错误 | 检查 `systemctl status smart-lab-backend` 与 Nginx `proxy_pass` |
| 浏览器 CORS 报错 | 后端允许域名未配置生产域名 | 检查 `SMART_LAB_CORS_ALLOWED_ORIGINS` |
| 登录后频繁失效 | JWT 密钥变化或多实例密钥不一致 | 固定 `SMART_LAB_JWT_SECRET`，多实例保持一致 |
| 后端启动失败 | 数据库连接失败、密钥长度不足或环境变量缺失 | 查看 `journalctl -u smart-lab-backend -f` |
| WebSocket 连接失败 | Nginx 未设置 `Upgrade` 与 `Connection` | 检查 `/ai-assistant/ws` 和 `/ws/ai-assistant` 配置 |
| Redis 健康检查失败 | Redis 未启用或密码错误 | 不使用 Redis 时关闭 `SMART_LAB_REDIS_HEALTH_ENABLED` |
| OSS 上传失败 | OSS 开关、Bucket、Endpoint 或 AK/SK 配置错误 | 检查 OSS 环境变量，确认密钥未过期 |
| 语音识别不可用 | Vosk 模型路径不存在或权限不足 | 确认 `VOSK_MODEL_PATH` 指向有效模型目录 |
| 课表采集失败 | Python、脚本路径或工作目录错误 | 检查 `TIMETABLE_CRAWLER_*` 相关变量 |

## 13. 安全与运维建议

- 所有密钥、数据库密码、OSS AK/SK 仅通过服务器环境变量或 `.env` 管理，不写入仓库。
- `.env` 使用 `chmod 600`，仅部署用户可读。
- 后端 `8080` 不直接暴露公网，通过 Nginx 反向代理访问。
- 生产环境固定 CORS 域名，不使用通配符。
- 定期备份 MySQL，至少保留最近 7 天备份。
- 发布数据库迁移前先在测试库验证，再在生产库执行。
- OpenAPI/Swagger 生产环境默认关闭；如需开启，应限制为内网访问。
- 若发生密钥泄漏，立即在云厂商控制台轮换密钥，并重启后端服务。
