# 扫码预约公开访问修复设计

## 问题与根因

实验室预约二维码指向公开前端路由 `/scan/reserve`。该页面挂载时先调用受登录保护的教学日历接口，再调用公开的实验室预约资料接口。匿名手机访问时，教学日历请求返回 401，全局 HTTP 拦截器随即跳转 `/login`，导致扫码预约表单无法显示。

## 目标

- 匿名用户扫描实验室预约二维码后直接进入预约表单，不被重定向到登录页。
- 已登录用户继续获得教学周信息。
- 保持现有公开预约资料、提交和状态查询接口不变。
- 不新增公开后端接口，不扩大匿名可读取的数据范围。

## 设计

`ScanReservation.vue` 根据当前会话状态决定是否加载教学日历：

- 已登录：加载教学日历；加载失败时仍保留现有错误提示语义。
- 未登录：跳过受保护的教学日历请求，直接加载公开实验室资料。日期和时段选择、表单校验、预约提交、状态查询均继续工作；只是不展示依赖教学日历的教学周辅助信息。

实验室资料加载必须独立于教学日历加载，不能因可选增强数据缺失而阻止公开预约主流程。

## 错误处理

- 公开实验室资料请求失败时，页面继续显示对应加载错误。
- 匿名访问不会产生受保护接口的 401，因此全局登录跳转不会被触发。
- 已登录用户的会话失效行为保持不变，仍由全局拦截器统一处理。

## 测试

新增前端边界回归测试，验证：

1. 扫码预约路由仍标记为公开路由。
2. 页面仅在已认证状态下加载教学日历。
3. 无论教学日历是否加载，公开实验室资料加载都会执行。
4. 现有前端测试与生产构建继续通过。

## 非目标

- 不改变二维码格式或链接地址。
- 不修改预约审批、冲突校验或预约状态流转。
- 不将教学日历接口改为公开接口。
