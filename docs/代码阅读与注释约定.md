# 代码阅读与注释约定

方法契约、事务并发、生命周期及协议注释的统一写法见 [工程化注释规范](工程化注释规范.md)。

## 容易误读的行为

- 前端路由、菜单和缓存决定页面体验，后端仍负责真正的接口权限校验。
- “记住我”保存账号选项与登录会话，不保存用户输入的登录密码。
- `CapabilityResult` 的不可用状态不同于成功查询后没有数据，不能将其当作“无冲突”。
- 教务域名可达不代表已登录；持久化授权标记也不保证学校 Cookie 仍有效。
- 采集的浏览器恢复最多尝试一次。验证码、学校身份认证和 aTrust 仍需正常授权。
- Python 输出文件后，由 Java 完成标准 CSV 的数据库导入；`parse_and_import_timetable.py` 保留了历史文件名。
- 当前采集锁和启动时遗留任务清理基于单后端实例。部署多个实例前需重新设计任务归属和锁机制。
- 不同端的在线阈值各有用途，不能把云端教师主机与本地学生设备阈值混为一谈。
- Prometheus 每 15 秒采样一次，采样时连接池“使用中为 0”并不等于没有数据库访问。

## 样式维护

`main.js` 中样式按组件库、基础布局、全局玻璃主题、按钮状态依次加载。通用透明度、边框和表面效果优先修改 `glass-theme.css`，按钮颜色与交互优先修改 `button-glass.css`。

页面负责布局和业务状态，避免在每个页面重复添加白色底或高优先级覆盖。弹窗和下拉菜单会挂到 `body`，主题选择器需要覆盖这些节点。固定表格列及下拉菜单保留更厚底色，防止与背后的文字重叠。

`useAdminGlass` 管理卡片材质，`useGlobalButtonGlass` 增量跟踪按钮；`attachLiquidGlass` 返回的清理函数必须在节点移除后调用。按钮仅交互时创建 SVG 滤镜，表格单元格不创建滤镜；`glassScrollActivity` 共享滚动监听并在滚动期间暂停背景采样。

## 注释写法

- 类或模块说明职责、输入来源、输出和外部依赖；复杂方法说明前置条件与异常含义。
- 行内注释解释业务约束、兼容原因、时间和数量单位，以及为何采用当前处理方式。
- 不给普通赋值、循环和 getter 重复写字面解释，不用猜测填充字段含义。
- 修改实现时同步修改注释；不把账号、密码、令牌、真实用户数据或机器特有路径写进示例。
- 避免把“当前实现”描述成不存在的保证，例如没有分布式锁时不称为跨实例互斥。

全项目文件级覆盖情况见 [全项目注释覆盖清单](全项目注释覆盖清单.md)。维护中的源码和支持注释的配置均提供文件或类型说明；JSON 和 SQL 的说明在清单中维护，避免破坏格式或迁移校验和。实体访问器、简单转发和生成代码不逐行添加重复注释。
