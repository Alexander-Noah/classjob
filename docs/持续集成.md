# 前后端持续集成

工作流位于 `.github/workflows/ci.yml`，在 push、pull request 和手动触发时执行。
范围为 Java 后端 `Backend` 和 Vue Web 前端 `web`；Python 采集器、教师端和学生端不纳入本轮门槛。

后端使用 Java 17、Maven 和 JaCoCo，执行测试、打包及全量生产代码行覆盖率检查。
独立 MySQL 8.4 服务启用数据库迁移、预约并发集成测试；测试只创建和清理自身随机命名的测试库。
前端使用 Node 24、锁文件安装、生产构建，以及 Vitest/V8 全量 `src` 源码行覆盖率检查。

两端分别要求至少 96% 行覆盖率。未执行的业务源码计入总行数；不通过修改统计范围或忽略失败来满足门槛。
已有测试通过不代表覆盖率达标，测试结果与覆盖率门槛会分别检查。
报告缺失或空报告也会导致失败。

2026-10-19 本地全量验证：后端行覆盖率 96.08%（8652/9005），504 项测试中 502 项通过、2 项 MySQL 集成测试默认跳过；
前端行覆盖率 96.01%（11064/11524），698 项运行测试、82 项静态检查及生产构建通过。
同日按 CI 命令再次验证：锁文件安装、生产构建、前端覆盖率检查通过；使用独立临时 MySQL 8.4 实例启用两项集成测试后，后端 504 项测试全部通过，无跳过，覆盖率仍为 96.08%。测试完成后已关闭临时实例。
以上为 Windows 本地验证结果；GitHub Actions 的 Ubuntu 工作流尚未远端执行。

Actions 页面可查看覆盖率摘要，下载保存 14 天的 `backend-test-reports` 和 `frontend-test-reports`，
包含测试结果及 HTML 覆盖率报告。即使覆盖率门槛失败，也会尝试上传报告。
工作流不会部署、发布或推送代码，也不需要生产数据库、学校门户或生产密钥。

本地执行：

```powershell
cd Backend
mvn -Pcoverage verify
cd ../web
npm ci
npm run build
npm run test:coverage
```

本地默认不启用需要 MySQL 的两项集成测试。CI 在其独立数据库服务中显式开启。
建议在 GitHub 分支保护规则中将 `Required checks` 设置为必需检查；仓库设置不会由本工作流自动修改。
