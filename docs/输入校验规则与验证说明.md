# 输入校验规则与验证说明

本次为项目加入共用输入边界，覆盖 Web/教师端共用请求层、Java Controller JSON 请求、查询及数字路径参数，AI WebSocket 文本消息，以及两份桌面端 Rust HTTP 请求入口。已有业务服务中的关联关系、库存事务和预约冲突检查继续执行。输入校验不替代权限校验、SQL 参数绑定或 HTML 输出转义。

## 规则与接入位置

| 层级 | 规则 | 实现 |
|---|---|---|
| 后端所有 Controller JSON | 最大 12MB、深度 20、总节点 50000、单对象 200 字段、单数组 1000 项；拒绝重复键、尾随多份 JSON、非法控制字符及原型污染字段名 | `RequestInputValidationAdvice`、`RequestInputValidation` |
| 后端字段类型 | 整数不能使用小数、数字字符串或超范围值；布尔字段必须为布尔值；文本不能被数字/对象自动转换；拒绝同一 DTO 字段同时提交多个别名 | `RequestInputValidation.types` |
| 查询和路径参数 | 查询最多 100 个参数，每个值 4096 字符；页码 1–1000000、每页 1–1000；数字路径编号必须为正且不溢出 Java 类型 | `RequestParameterValidation` |
| 账号 | 账号必填、最多 100 字符；创建/改名不允许空白；密码最多 128 字符，创建/修改仍要求现有复杂度；登录不强迫历史密码使用新复杂度；姓名、部门、联系方式、邮箱按字段长度和格式限制 | `AccountInputValidation`、`UserServiceImpl` |
| 账号权限字段 | 状态只接受 0/1；角色只接受未停用的 systemAdmin/labAdmin/academic；批量编号 1–1000 项，禁止小数截断、溢出和静默跳过错误项 | `UserController`、`UserServiceImpl` |
| 密码存储 | 外部提交的新密码一律重新哈希，不因字符串形似已编码密码而直接写库；缺少账号不再自动生成用户名掩盖漏填 | `UserServiceImpl` |
| 业务输入 | 实验室/设备/耗材名称必填；容量、库存、数量、预警值、使用时长及维修进度限制范围；端口 1–65535；客户端登记必须提供正 labId 和设备标识；课程名、通知标题/内容必填；实验室/调课状态使用允许值集合 | `RequestInputValidation.domain`，包括嵌套批量 DTO |
| Web 与教师前端 | 发送前采用同一份长度、结构、整数及非法字符规则；登录输入框加入长度限制和错误提示；校验不改写密码或业务正文 | `shared/requestValidation.js`，由两个 Axios 请求层使用 |
| AI WebSocket | 复用长度/深度/重复键校验，校验消息类型及状态；保留普通文本问答兼容，拒绝非法协议内容 | `RequestInputValidation.websocketText` |
| 桌面 HTTP | 读取上限 64KB，结构深度 12，动作仅接受 refresh/message/lock/reboot/shutdown；消息最多 1000 字符、requestId 最多 128 字节；错误参数在创建动作线程前拒绝 | `shared/desktop_input_validation.rs`，由两份 Rust lib.rs 使用 |

普通输入不会采用“SQL 关键词/尖括号一律禁用”的黑名单：中文、英文标点、`O'Brien`、正常多行说明可通过；SQL 注入防护仍依靠参数绑定。密码不做 trim。

长内容有单独限额：普通未知文本 16000 字符；说明/备注 4000；正文与 AI 文本 100000；教务 HTML 2Mi 字符；显式图片/音频字段 8Mi 字符，同时仍受整个 JSON 12MB 上限约束。图片采用 `image_url.url` 的格式也已兼容。对于新的业务字段，应在公共规则中声明需要的专属限额，而不是关闭校验。

## 接口行为变化

- 以前允许的小数转整数、数字冒充文本、重复 JSON 键、无效用户编号等，现在返回 400；正文超过总上限返回 413。
- 数字下拉选项如果在表单内部使用字符串，应在业务构造提交对象时明确转换并校验，而不是由后端进行隐式转换。
- 一次提交超过 1000 条的全量台账需要业务上设计分页/增量提交。**不能直接把全量替换接口拆成多个替换请求，否则后一次会覆盖前一次。** 本次只加入拒绝上限，未重写全量替换语义。
- 不自动清洗或删掉不合法数据，不把错误的数量改成默认值后继续提交。已存在的历史记录不会被批量迁移；编辑不符合新约束的记录可能需要纠正字段。
- 通用输入边界没有把角色归属、审批权限及所有业务状态流转转换为安全策略；这些仍需按安全审查报告独立修复。

## 最终验证（2026-10-19）

Web 88 项基础测试与 708 项组件测试全部通过，行覆盖率 96.00%；后端 522 项测试全部通过、无跳过（含隔离 MySQL 集成测试），行覆盖率 96.009%，生产构建与最终 JAR 浏览器联调通过。此前三项旧展示断言已按现有文案与对话框组件修正。

客户端按用户要求不打包；生产代理/TLS、真实设备动作、压力测试、上传文件内部全部业务语义及 Python 导入脚本不在本轮验证范围。详细结果见《Web与后端发布验证-2026-10-19.md》。
