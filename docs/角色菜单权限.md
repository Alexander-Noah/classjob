# 角色菜单与页面访问权限

系统管理员（现有 `systemAdmin`，即本功能的超级管理员）登录后，打开 **角色菜单权限**，地址为 `/system-admin/role-access`。

1. 选择要管理的角色。
2. 设置每个页面的“允许访问”和“显示菜单”。显示菜单必须同时允许访问；允许访问但不显示菜单时，可以通过地址或页面内链接进入。
3. 保存后，同角色成员下次导航或刷新时读取最新配置；对应受控业务接口每次请求均读取服务端配置，旧令牌不会绕过撤销结果。

工作台、超级管理员的权限配置入口固定保留，防止配置后无法进入管理。可以选择“仅保留必要入口”关闭其他页面，空授权不会解释为“全部开放”。未保存过角色配置时兼容原有默认页面。

角色配置是现有角色业务范围的进一步限制，不能跨角色开放其他工作台。现有账号个人权限仍作为额外限制：角色页面权限和个人权限都允许时才能进入。现有暂停角色只读展示，不通过本功能恢复登录。当前已有页面目录覆盖系统管理员、实验室管理员及暂停的教师；未定义工作台的历史角色不会新增虚构页面。

服务端沿用现有 `module_record` 持久化，每个角色使用 `role-page-access-{roleCode}` 模块，不需要新增数据库表或迁移。规则页面目录为 `Backend/src/main/resources/security/role-pages.json`，增加前端路由时须同步目录及该页面的业务接口规则，自动测试会检查页面目录覆盖。

接口：

- `GET /auth/page-access`：当前已认证角色的页面和菜单配置，不接受调用方指定其他角色。
- `GET /role-page-access`：超级管理员读取角色列表。
- `GET /role-page-access/{role}`：读取页面目录和配置。
- `PUT /role-page-access/{role}`：保存 `accessiblePaths`、`visiblePaths` 字符串数组；拒绝跨角色路径、未知页面及没有访问权限的可见菜单。

服务端角色检查保留原有接口上限，在此基础上限制页面目录绑定的业务接口。工作台聚合数据、公共资料、上传等共享接口继续服从原有授权，不通过隐藏菜单单独限制共享能力。AI 长连接建立及每条消息均检查页面授权，已建立连接在撤销后发送下一条消息会被关闭。

页面所需的共享查询也绑定到该页面。例如只开放设备状态或设备资产、关闭实验室资源时，仍允许 `GET /labs` 为该页面提供实验室列表，但不开放实验室详情、创建、编辑、删除或实验室资源路由。维护记录表单同样需要只读设备列表；环境、预约、使用记录、物联及统计页面的查询依赖也在目录中显式列出。统计页面本身包含跨模块数据汇总，授权该页面即允许其列明的汇总来源列表读取，不会连带开放这些模块的写接口。系统管理员平台统计依赖账号和公告列表读取，配置授权时应同时考虑这些数据的可见性。

上述依赖按请求方法和精确路径匹配，不使用全局 GET 放行；撤销全部依赖页面后，查询仍受原模块页面授权约束。设备状态主数据加载失败会提示错误并清空实验室/设备状态，不显示示例实验室。

前后端需同时更新并重启后端。权限接口缺失、重启或请求失败时，工作台和超级管理员权限配置入口始终保留；其他页面显示“权限服务暂不可用”，而非误报 403。重新加载权限可重试原目标页面。服务异常不会开放可选业务页面，也不会清空数据库已保存的角色规则。

本次验证包含前端生产构建、页面勾选与保存、路由地址拦截、空授权、跨角色拒绝、HTTP 403 及 AI 长连接撤销。未向现有开发数据库写入实际限制规则，首次打开仍沿用原有默认权限。
