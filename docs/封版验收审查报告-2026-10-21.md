## 3. 问题清单

### F01：账号状态和角色变更不能及时撤销旧 JWT

- **模块/位置：** `Backend/src/main/java/org/example/backend/security/JwtAuthenticationFilter.java:100`、`JwtService.java:89`、`service/impl/UserServiceImpl.java:193`、`:296`、`controller/UserController.java:89`。
- **问题：** 请求认证信任令牌内的角色和用户标识，没有检查当前账号状态、当前角色或撤销版本；退出接口不使已签发 JWT 失效。默认有效期为 7200 秒。
- **证据：** 静态确认；隔离运行验证修改签发源用户对象后，旧令牌仍有效且仍含旧角色。这不是实际数据库禁用账号测试。
- **复现：** 测试账号登录保存 JWT；管理员禁用/降权账号后，用旧 JWT 直接请求原有受保护接口，检查是否仍获授权。注销、删除和密码重置也应分别验证。
- **影响：** 账号撤权存在窗口，已泄漏令牌不能及时收回；新登录状态不代表旧会话已失效。
- **风险：高。封版前必须修复：是。**
- **最小建议：** 在现有认证链校验缓存/数据库中的有效账号与权限版本；相关变更撤销旧版本，同时检查 WebSocket 会话的撤权行为。

### F02：用户个人页面权限缺少后端等效约束

- **模块/位置：** `web/src/router/index.js:480`、`web/src/constants/permissions.js:75`；`Backend/src/main/java/org/example/backend/security/RoleAuthorizationFilter.java:72`、`service/RolePageAccessService.java:84`。
- **问题：** 前端使用 `user.permissions` 限制个人页面；后端检查角色和角色页面策略，不读取该用户的个人权限。角色页面策略不能替代个人配置。
- **证据：** 静态确认授权链；尚未用真实受限账号执行 API 越权复现。
- **复现：** 在隔离库中给实验室管理员角色开放设备页面，但给该账号仅授权实验室页面；前端访问设备被拒后，用其 JWT 请求 `/devices`，核对后端结果。
- **影响：** 个人权限界面展示的限制可能被直接调用接口绕过。
- **风险：高。封版前必须修复：是，若现有个人权限继续作为授权能力交付。**
- **最小建议：** 后端按现有权限定义求角色策略与个人策略的有效交集，明确空权限的兼容语义，并补直接 API 测试。

### F03：AI 操作确认拒绝真实认证链生成的用户 ID

- **模块/位置：** `Backend/src/main/java/org/example/backend/security/JwtService.java:377`、`JwtAuthenticationFilter.java:107`；`controller/AiBusinessActionController.java:18`。
- **问题：** JWT 用户 ID 是 `String`，过滤器原样写入请求属性；确认接口只接受 `Number`，合法登录请求也会得到“请先登录”。现有 Controller 测试手工传数字，绕过了该差异。
- **证据：** 隔离运行真实 JWT 服务、过滤器及 Controller 已复现：`jwtUserIdRuntimeType=String`、确认被拒；业务执行依赖为 Mock。
- **复现：** 正常登录后生成待确认 AI 操作，再确认；或用真实过滤器生成请求属性后调用确认方法。
- **影响：** AI 业务确认链路无法闭环。
- **风险：高。封版前必须修复：是。**
- **最小建议：** 确认接口安全解析现有认证 ID，统一契约；补包含认证过滤器的确认/拒绝测试，避免扩大修改其他接口。

### F04：课表学期替换缺少数据库事务保护

- **模块/位置：** `Backend/src/main/java/org/example/backend/service/impl/ClassTimetableServiceImpl.java:665`、`:698`。
- **问题：** CSV 解析后先删除对应学期，再逐条插入；该写入链没有事务边界。中途数据库异常可能留下空学期或部分课表。仅给当前私有自调用方法添加事务注解也不能形成 Spring 代理事务。
- **证据：** 静态确认；没有在业务库注入插入故障。
- **复现：** 在隔离库准备旧学期数据，让第 N 次插入失败；检查失败后旧数据是否完整保留、是否出现部分新数据。
- **影响：** 课表数据丢失/不完整，进一步影响预约冲突判断及查询结果。
- **风险：高。封版前必须修复：是。**
- **最小建议：** 文件解析完成后，用现有事务设施将删除和全部插入包在一个短事务内；验证失败回滚，不把浏览器抓取包进长事务。

### F05：课表解析失败返回成功，旧 CSV 可能被再次导入

- **模块/位置：** `Backend/Python/parse_and_import_timetable.py:288`、`:304`；`Backend/src/main/java/org/example/backend/service/impl/ClassTimetableServiceImpl.java:269`、`:665`。
- **问题：** HTML 不存在或解析结果为空时 `return`，进程退出码仍为 0；固定路径中的上次 CSV 未失效。后端在解析成功退出后读取该固定文件，无法证明其来自当前任务。
- **证据：** 两个隔离子进程场景均已复现退出码 0 且旧 CSV 内容不变；未进行最终业务库导入。
- **复现：** 临时目录先放旧 CSV，再分别提供缺失 HTML 和空表 HTML，运行解析脚本，检查退出码及 CSV；随后核对后端成功分支。
- **影响：** 抓取失败被记录为成功，旧数据被误当新数据导入，定时任务产生虚假成功。
- **风险：高。封版前必须修复：是。**
- **最小建议：** 无有效输入/输出必须非零失败；后端验证当前任务产物及有效记录，拒绝旧文件。同步核对爬虫无结果导出分支的退出状态。

### F06：角色页面授权没有覆盖页面必需的共享查询

- **模块/位置：** `Backend/src/main/resources/security/role-pages.json`、`service/RolePageAccessService.java:84`；`web/src/views/device-status/DeviceStatusPage.vue:388`、`:399`；`web/src/composables/useDeviceManagement.js:170`。
- **问题：** 允许设备状态页面、禁用实验室页面时，页面依赖的 `/labs` 查询被拒。设备管理下拉框也依赖该查询。设备状态失败分支还使用 `FALLBACK_LABS` 示例实验室，可能掩盖真实查询失败。
- **证据：** 隔离执行真实策略服务，设备状态主接口允许、其 `/labs` 依赖拒绝；具体页面运行效果待登录浏览器验证。
- **复现：** 测试角色仅开放设备状态/设备管理，关闭实验室管理；重新登录访问，观察 `/labs` 403、下拉框与实验室展示。
- **影响：** 超级管理员配置合法权限组合后，已授权页面仍无法完整使用，甚至出现示例数据。
- **风险：高。封版前必须修复：是。**
- **最小建议：** 在现有 API 映射中明确页面所需的只读查询依赖，避免连带授予实验室写权限；生产请求失败显示真实失败/空状态，不能显示示例数据。

### F07：设备注册、心跳和上下线接口缺少可见的调用方身份验证

- **模块/位置：** `Backend/src/main/java/org/example/backend/security/JwtAuthenticationFilter.java:44`；`controller/TeacherHostController.java:38`、`StudentClientController.java:35`、`:45`；对应 `TeacherHostServiceImpl`、`StudentClientServiceImpl`、Mapper。
- **问题：** `/teacher-hosts/**`、`/student-clients/**` 及别名跳过 JWT；检查到的写入链主要验证实验室/设备参数，没有验证调用方拥有该设备。心跳持久化请求提供的主机地址等信息。
- **证据：** 静态确认；本机匿名无效参数请求到达 400 校验。没有发送匿名写请求，也没有证实远程控制接管。
- **复现：** 隔离库中匿名提交另一设备的心跳或离线请求，检查记录是否被覆盖；同时核实生产网络边界。
- **影响：** 在不可信网络可达时，可能伪造在线状态、主机发现信息或设备离线状态。
- **风险：高。封版前必须修复：条件性必须；若保留网络隔离作为边界，必须提供并验证隔离证据。**
- **最小建议：** 使用现有设备激活/凭据体系验证写入身份及设备归属，必要的发现读取按明确的可信网络范围开放。
